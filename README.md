# Rental Housing Law Navigator

**Live demo:** https://ruby4578.github.io/rental-housing-law-navigator/

An AI pipeline that reads US state and city housing law and tells you which rules apply to a rental address, with a verified citation for every rule.

> **Not legal advice.** This tool summarizes public law to help people understand it. It is not a legal opinion or a compliance check. Ask a qualified attorney or your local housing agency before you act.

Built solo by **Eshaal Abid** (team **Single Thread**), first-year Computer Engineering student at the University of Naples Federico II.

## What it does

Renting rules change by city, state and date. Given one of 500 sample addresses in California, Massachusetts and New Jersey, the navigator shows which rules in six categories apply, which don't, and which can't be decided from the data:

- rent increase limits
- just-cause eviction
- security deposits
- application and screening fees
- screening restrictions
- algorithmic rent-setting

Every result is one of: **applies**, **unknown**, **superseded**, **not yet effective**, or **pending**. A date control shows the rules as of a chosen day.

## Design principles

1. **No invented rules.** Every extracted rule carries a quote that is checked to appear word for word in the source document. Records that fail are rejected, or repaired to the longest passage that really exists in the source.
2. **Unknown beats a guess.** If a rule depends on a fact the data lacks (year built, unit count, owner type), the answer is "unknown" and says which fact is missing.
3. **Sources are visible.** Each rule links to its source document and shows the supporting quote.
4. **Nothing on the page is typed by hand.** The page reads `data.json`, which is generated by the scripts below.

## How it works

```
corpus/text/*.txt ──► extract.py ──► cache/ (raw model output = audit log)
                                        │
                                  finalize.py ──► rules.json
                                        │
sample_addresses.csv ─────────────► lookup.py ──► lookups.json
change_tests.json ────────────────►            ──► changes.json
                                               ──► data.json ──► index.html
```

| File | Role |
|---|---|
| `extract.py` | Sends each corpus document to an LLM (Groq, `openai/gpt-oss` models) and caches the raw output. The LLM call is isolated in one function, so the provider can be swapped. Retries on rate limits. |
| `finalize.py` | Reads the cache, checks every quote against the source text, repairs near-miss quotes, validates against `rule_record.schema.json`, and writes `rules.json`. Makes no API calls. |
| `lookup.py` | Resolves each address to a city, tests each rule's coverage (year built, units, state vs local), computes the T1–T5 change tests, and writes `lookups.json`, `changes.json`, `resolved_addresses.json` and `data.json`. |
| `index.html` | Static web demo that loads `data.json`. |

## Results

- **100 rules** extracted from **43 of the 87** corpus documents, each with a verified quote and 0 rejected after repair.
- **500 addresses** looked up (11,990 address-rule results).
- Change tests (as of 2026-10-01):

| Test | Result |
|---|---|
| T1 California pricing-algorithm law takes effect | 250 California addresses affected. See limitations for the effective date. |
| T2 Hoboken vs Jersey City local bans | 0 affected. These ordinances are not in the corpus. |
| T3 NJ FAIR Act (effective 2027-07-01) | 140 NJ addresses affected as not yet effective. 0 conflict flags, because the local rules it would conflict with were not found. |
| T4 Massachusetts pending bills | 110 MA addresses affected for S.2983, reported as pending, not in force. H.5222 was not found. |
| T5 Massachusetts rent-control ballot question | 0 affected. No rent cap is reported. |

## Run it yourself

```bash
pip install requests python-dotenv jsonschema
```

Create a `.env` file (never commit it) containing:

```
GROQ_API_KEY=your_key
GROQ_MODEL=openai/gpt-oss-120b
```

Then:

```bash
python extract.py                      # extract rules from corpus/text/ (cached in cache/)
python finalize.py                     # verify quotes, build rules.json
python lookup.py --rules rules.json --addresses data/sample_addresses.csv \
                 --tests dev/change_tests.json --no-geocode
```

Open `index.html` through a local server (for example `python -m http.server`) to view the demo. Drop `--no-geocode` to use the Census Geocoder.

## Known limitations

These are real gaps, listed so nothing is hidden:

- **Incomplete extraction.** Only 43 of 87 documents were processed. The Groq free tier hit its daily limit partway through the very large document D067, and the rest of the corpus was not reached.
- **Missing local rules.** The Hoboken and Jersey City algorithmic-pricing ordinances, and Massachusetts bill H.5222, are not in the processed documents, so T2 is empty and T4 covers only S.2983. Nothing was invented to fill the gap.
- **California effective date.** The source text of the California pricing-algorithm law does not state when it takes effect, so its date is left empty rather than guessed. T1 therefore cannot show "not yet effective" before 2026.
- **Low-confidence cities.** The Census Geocoder was unreachable from the development environment, so each address's legal city comes from its mailing city and is flagged low confidence. Cases such as Van Nuys (part of Los Angeles) need geocoding to resolve correctly.
- **Missing address facts.** Unit counts for many addresses and owner type for all of them are absent from the data, so many results are correctly "unknown".
- **Berkeley's algorithm ordinance** passed to print in November 2025 and the text gives no effective date, so it is flagged for human review.

## Tools

Python, the Groq API (OpenAI open-weight models), the US Census Geocoder (optional), GitHub Pages. Developed with AI assistance, and every extracted rule is checked against its source text by code rather than trusted.
